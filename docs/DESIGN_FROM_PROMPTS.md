# 从 Prompt 库到可验证应用

## 审计结论

原仓库的强项是把学术任务拆成清晰步骤：生成搜索式、筛选来源质量、区分经典与前沿、按理论/方法/应用分类、寻找最接近工作、建立综述矩阵。它的局限是部分流程让通用模型直接回忆论文，再要求用户去 Google Scholar 验证；这种顺序无法从源头阻止虚构引用。

LitWatch 将顺序改为：

1. 从 OpenAlex、arXiv、Semantic Scholar 获取真实记录；
2. 用 DOI、arXiv ID 和标题去重；
3. 用确定性评分完成低成本初筛；
4. 只把已验证的标题、作者、摘要或开放全文交给分析 Prompt；
5. 保存证据级别、评分分项和来源链接；
6. 输出网页、邮件、Zotero 或 BibTeX。

## Prompt 到功能的映射

| 原方法 | 应用功能 | 防幻觉约束 |
|---|---|---|
| 生成关键词和搜索式 | 快速检索表单、主题 YAML | 查询发送到真实 API |
| 快速筛选论文 | 五维确定性评分 | 分项可追溯 |
| 分级论文清单 | 快速筛选分析模式 | 只能评价输入论文 |
| 理论/实证/方法/应用分类 | 综述矩阵模式 | 未提供证据时明确标注 |
| 经典与最新工作 | 经典与前沿模式 | 年份、引用量来自数据源 |
| 论文对标 | 最接近工作模式 | 不允许补充未检索论文 |
| 完整论文数据库 | SQLite + Web 页面 | 保留来源 ID 与运行记录 |

## 适合水声与水下机器人方向的默认模式

- 日常周报：`quick_scan`
- 准备文献综述：`review_matrix`
- 新方向入门：`seminal_frontier`
- 检查选题重复：`closest_work`

这些模式定义在 `config/analysis_modes.yaml`，可以独立调整，无需修改 Python 代码。
